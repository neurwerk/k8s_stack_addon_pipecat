# Private scripts

The bundled public example needs no object store. Private scripts are trusted administrator code, not user uploads or a sandbox; they run with the bot's credentials and network permissions. Review them like runtime code. All Python dependencies must already be in the reviewed image; neither init nor runtime performs pip downloads.

Set a bot's `script.enabled`, `endpoint`, `bucket`, immutable object `key`, exact archive `sha256` and `secretName`. The init-only Secret has `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`. Runtime does not receive S3 credentials. It sees only the read-only `/scripts/bundle`. The loader checks SHA-256 before parsing and limits decompression, expanded bytes and file count; it rejects links, devices, duplicate paths, absolute paths and traversal. Only a fully validated bundle is atomically published. Use regular files without directory headers in the tar.gz.

Include root `manifest.json` with `runtimeVersion` equal to the runtime package's exact version and `entrypoint` naming a root Python file, for example `bot.py`. It exports `async run_bot(connection, settings, http, credential, notice)`, the same signature as `neurwerk_pipecat.example.run_bot`. Reuse the runtime's HTTP speech and gateway adapters to preserve credential and PII boundaries; bypassing them is a private script's reviewed responsibility. Do not add transcripts, Secrets or dependencies to the archive.

For optional Rook storage, set `pipecat.scriptStorage.enabled`, `store`, `clusterNamespace` and `bucket` in the shared chart. The chart creates a retained bucket StorageClass, bucket claim, read-only `pipecat-script-reader` and separate `pipecat-script-publisher` users. Rook generates `rook-ceph-object-user-<store>-pipecat-script-reader` with `AccessKey`/`SecretKey`; setup must map only those reader fields into the init Secret's AWS field names. Never mount publisher credentials into bot pods. The publisher owns object writes/deletion; the reader policy grants only object reads. Wait for Rook user Secrets, bucket binding and optional ExternalSecret readiness in the client Flux graph. Retain the namespace, bucket and users during uninstall; deletion requires separate operator approval and independent backup planning.
