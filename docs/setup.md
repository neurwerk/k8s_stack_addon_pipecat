# Configuration and setup

## Release graph

The client owns `pipecat-addon` source selection and Flux packages: `namespaces` → `setup` → `app`, using paths from `release/manifest.yaml`. Wait for each package. Setup configures credential delivery, Base's `keycloak/addon-access` and `keycloak/addon-oidc`, bridge grant descriptors, optional coturn and certificate approvals. App depends on identity, AgentGateway, Traefik and certificate issuers. The shared release does not wait for optional TURN startup/certificate issuance, so pending public media routing cannot block HTTPS WebSocket fallback. Check TURN separately before claiming WebRTC relay availability. Select Rook/External Secrets only when using their optional features; add the corresponding Flux dependencies and generated Secret/user/bucket health checks before their consumers.

Set `pipecat.enabled` and `pipecat.hostname` in shared client values. Supply `pipecat-product-values` and `client-values` in `pipecat`, `auth-keycloak` and `auth-keycloak-api-key-bridge`; also supply shared `client-values` in `infra-cert-manager`. Product values include the exact published runtime image reference with full version and independently verified digest. There is intentionally no default runtime image. Never use `validation/values.yaml` for deployment. `release/credentials.yaml` fixes the setup Secret names, fields, OpenBao mapping and managed identity format; select the new catalog and reconcile those credentials before claiming they exist.

## Bot settings

`charts/pipecat/app/values.yaml` and its schema define the inputs. Each bot has a kebab-case Kubernetes `id` and optional independent `urlSlug` accepting underscores: `id: simple-chatbot`, `urlSlug: simple_chatbot` serves `https://<hostname>/simple_chatbot/`. Set `anonymous` explicitly. `sessionsEnabled` defaults to false: UI, health and Keycloak can deploy without model or speech settings, while all voice admission is denied and the page clearly says voice is unavailable. Enable it only with configured `bindingId`, canonical `modelId` and `stt`/`tts` objects (`baseUrl`, `model`, optional `secretRef: {name, key}`, TTS `voice`, STT `language`). Model requests always use `pipecat.gatewayOrigin` + `/bindings/<bindingId>/v1/chat/completions`, never a direct provider URL. Select an existing canonical model ID, not a provider alias.

STT uploads bounded VAD-segmented WAV to `/audio/transcriptions` with `response_format=json`. TTS streams `/audio/speech` with `response_format=pcm`: signed little-endian PCM16, 24 kHz mono, not WAV or encoded audio. These external speech endpoints have separate credentials and do not inherit gateway access. Verify transport-level privacy requirements for these services separately; the model gateway's PII protection does not process the raw microphone stream.

`sessionSeconds` bounds calls and browser sessions, `idleSeconds` bounds pipeline inactivity, and `maxConnections` bounds concurrent calls. One active call per browser session is allowed. Restarts lose sessions, and protected sessions end no later than the access-token expiry; sign in again rather than falling back to a bot key. There is no token refresh or persistent conversation history.

## Identity and credentials

Protected bots require `pipecat.oidc.issuer`. The shared confidential browser client defaults to `pipecat`; its callback allowlist contains each protected bot's exact `/<urlSlug>/auth/callback`, with HTTPS web origin matching `pipecat.hostname`. Supply `pipecat-oidc-approval-values` in `auth-keycloak`, with explicit `clientApproval.clientId`, `realmRoles: [pipecat-user]`, `audiences: [agentgateway]` and approved `gatewayPermissions`. These scope only existing user permissions and do not grant model access. Set `pipecat.oidc.gatewayPermissions` to the same reviewed scope, including invocation and company-use permissions where appropriate. Base must allow this OIDC client and the selected bindings as approved gateway callers. Use `/access/neurwerk-pipecat-users` for admission.

Provision matching Secret `pipecat-oidc-secret`, field `clientSecret`, in `auth-keycloak` and `pipecat` before setup. Existing Secret references work without any assumed generated values. Approved OpenBao delivery can use `pipecat.secretDeliveries` in the shared chart (`name`, `storeName`, `fields: [{key, path, property}]`); the auth namespace's OIDC Secret is delivered by client/setup tooling. Keep private paths and credentials in client-owned configuration. Controllers retain remote credentials on source deletion; removing an app is not permission to delete its Secrets or data.

Anonymous bots must explicitly set `anonymous: true`. Enabled anonymous sessions read `pipecat-bot-<id>/gatewayApiKey` by default; `gatewaySecretRef: {name, key}` can select an existing narrowly scoped key instead. Protected bots reject that field. For managed keys, configure each anonymous bot's `gatewayPermissions`; `pipecat-gateway-registrations` produces its version-2 grant ConfigMap with distinct `service_account` principal `client_id: pipecat-bot-<id>`. Setup provisions the account's intersected llm/model/provider grants and matching SHA-256 verifier, and the client adds the documented pair to Base's generic `authKeycloakApiKeyBridge.managedRegistrations`. Never use the browser OIDC client as the bot service-account client. There is no credential fallback or backend gateway bypass. Every signaling operation and WebSocket ticket checks its opaque session owner; cookies are secure, HttpOnly and path-scoped. OIDC uses state, nonce, PKCE and signature/issuer/audience/expiry/authorized-client validation. Tokens stay on the server.

## WebRTC networking

No public STUN server is configured. Enable chart-managed coturn with `pipecat.turn.enabled`, `hostname` and the default `pipecat-turn-secret/sharedSecret` (64 lowercase hexadecimal characters). The shared secret stays server-side; runtime issues limited-lived HMAC TURN REST credentials to each authenticated/explicit anonymous session and to server ICE. `iceServers`/`browserIceServers` support additional non-secret URLs, and `iceSecretRef`/`browserIceSecretRef` support external credential-bearing JSON arrays. TURN credentials are not refreshed during a call.

Expose UI/signaling and WebSocket fallback over ordinary Traefik HTTPS 443. Coturn has a separate cert-manager TLS certificate for its exact hostname, approved by the add-on certificate policy; the selected platform's DNS01 issuer does not require HTTP challenge forwarding. Its single pod uses explicit NodePorts: UDP 30478 → 3478, TCP 30549 → TLS 5349, and UDP relay range 31000–31015 mapped port-for-port. Pin it with `turn.nodeSelector` and forward only the node actually running it (`externalTrafficPolicy: Local`). Later operator-owned edge configuration must pass TLS through to that node's TLS NodePort, forward the UDP listener and relay range, preserve source/return routing, and set `turn.advertisedAddress` to the matching public IPv4 address. No edge/EC2 changes are performed by this repository. An empty advertised address permits startup but does not establish an Internet relay. Coturn refuses loopback/private/multicast peers and has quotas; the upstream executable requires its `NET_BIND_SERVICE` bounding capability even though configured pod ports are unprivileged. Restart coturn after certificate renewal to load the new keypair.

The browser tries WebRTC first, with a 15-second networking timeout after microphone permission. Only an initial connection failure permits a clean disconnect/cancel and one WebSocket attempt with a fresh single-use, session-bound ticket. Permission, authentication and model/service errors do not trigger fallback. There is no seamless mid-call switching. WebSocket uses Pipecat's browser development/testing transport (bounded PCM16 microphone frames at 16 kHz mono and playback at 24 kHz); browser support, echo handling, latency and reconnection are less mature than WebRTC. Verify it manually before broader use. It requires no functioning TURN relay, but does require working HTTPS/WebSocket routing and microphone permission.

Fill `pipecat.egress` with narrow peers/ports for identity/JWKS, gateway, speech, optional S3 and TURN; only DNS is allowed by default. Treat public TLS routes, TURN reachability, WebSocket/media behavior and inference readiness as separate acceptance checks, never inferred from pod health.

PII Engine notices remain enabled and appear in the browser's notice panel. The streaming adapter keeps the appended report out of TTS and ordinary assistant history. Structured reasoning/tool deltas are not spoken; this example does not execute tools. No model endpoint calls are needed for offline checks.
